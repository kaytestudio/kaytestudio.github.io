Detailed Description

Runtime support for -fstack-protector-strong.

Every function clang decides is worth protecting (has a local array or address-taken local buffer) stores __stack_chk_guard as a canary on the stack at entry and compares it again before returning; a mismatch means something has already overflowed a local buffer and corrupted the stack, so __stack_chk_fail() must never return - continuing would run on untrustworthy state (corrupted saved registers/return address).

This is the same class of "freestanding runtime support the compiler assumes exists" as MSVC's __security_cookie/__security_check_cookie (see wiki.osdev.org/Visual_C%2B%2B_Runtime) - clang/GCC's equivalent for -fstack-protector, needed here because CMakeLists.txt used to build this whole project with -fno-stack-protector specifically because these two symbols didn't exist yet.
